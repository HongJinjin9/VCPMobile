### 自动提取与人工判断的边界

| 数据 | 提取方式 | 能证明的事实 | 不能据此证明 |
|---|---|---|---|
| Plugin/app 注册 | 识别实际 `generate_handler!` token 列表 | 命令名和注册路径 | 当前平台能成功执行 |
| 前端调用 | TypeScript AST 的 `invoke(...)` 及实际调用的 guest wrapper；解析字面量和常量命令参数 | 真实调用表达式、import 来源和位置 | 用户必然走到该分支 |
| 前端潜在可达性 | 从 `src/main.ts` 沿静态 import/export 与字面量动态 import 展开 | 是否处于主应用模块图 | 符号级 tree shaking、条件渲染或运行时功能可达性 |
| Rust 消费 | 去除注释、字符串及确切 `#[cfg(test)]` 块后匹配调用表达式 | 插件限定调用、`ForegroundLease::acquire`、CLI bridge 调用位置 | 完整 Rust 名字解析、任意宏展开或目标 cfg 真值 |
| 原生桥 | `run_mobile_plugin*` 的 selector 参数；另外识别当前 `pty_bridge!` 输入 | selector 与调用函数、位置 | Swift 同名 selector 的线程、生命周期和 DTO 正确性 |
| Kotlin | `@Command` + 函数声明 | 原生桥可调用 selector 集合 | 已向 Vue 授权或公开 |
| ACL | build/default/all/生成命令/schema/reference 集合及 capability JSON | 当前集合一致性与声明范围 | 运行时拒绝策略已验证 |

脚本不会把普通字符串、注释、测试断言、`use`/`import` 声明或 guest wrapper 的定义本身算作消费。Vue 只解析 script，Rust 不构建完整调用图；模板内直接调用、特殊别名/namespace、非字面量动态 import、一般宏、函数指针和目标分支仍需按对应 owner 人工核对。因此“未找到消费者”是本次范围内的证据结论，不自动授权删除命令。

## 6. Melchior 审查意见

1. **IPC 与线程**：保留 app command 一次中央 offload。Plugin path 是另一条 dispatch 路径；Apple 主线程操作、同步/异步 bridge 与 Channel callback 必须分别审查，不能从 Android worker 总闸推导 Swift 已安全。
2. **资源所有权**：`ForegroundLease` 的 tag、非 Clone 所有权与 Drop 释放是已有资产。Chat（agent/group）、Sync、预渲染与 Distributed 的消费者均已存在；新增 iOS native task 必须绑定同一 attempt/terminal owner，不能另建与业务终态无关的“成功租约”。
3. **取消与回调生存期**：`events.rs::subscribe` 明确等待最终 native response。业务取消后仍要让 bridge 接收迟到返回，再由 generation 决定是否应用；不要用 timeout 丢弃 native response future 伪造完成。
4. **类型完整性**：permission bool 不是 capability；`open_file_native` 的意图也不等于当前平台支持。首期改 DTO 时应沿 JSON 中的真实消费者一次闭合字段、错误与可选值，禁止兼容假数据成为 iOS 路径。
5. **内存与输入边界**：文件/图片按路径或 ticket 交接，尤其复查 `write_temp_file` 的 JSON 数组、`save_to_downloads` Base64、原生图片解码及 CAS 副本。容量判断必须覆盖进入 adapter 前的 IPC 分配与并发，不能只审视写盘后大小。

本项 Phase 0 完成的是“集合、消费证据、源码缺口与任务归属”。它给 Phase 1–5 提供定位输入，不替代目标编译、Swift 链接或平台行为的阶段验收。
