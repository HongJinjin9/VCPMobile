# Phase 0 子规划：把研究输入变成可施工清单

> 历史子规划：2026-10-08，`4c6e25bb` 加当时工作树。2026-10-09 仅校准沿革；原任务和完成条件用于解释阶段证据，不要求重新实施。当前交接见 [04](./04-核心路径与阶段交接清单.md) §3 与 [05](./05-验收记录与Magi交接.md) §4。

## 当时目标与边界

用户于 2026-10-08 启动 iOS 兼容并要求每个 Phase 使用专属子目录。沿用总路线的 Phase 0：固定输入、恢复产品决定、目标源码审计。本轮产出可复查的事实、规范与后续任务；平台能力、Swift 插件和业务适配分别从 Phase 1/2/3 开始。

Android 现有生产能力及用户未提交修改保留。Apple 构建沿用 D14，只在阶段性手动 GitHub Actions G1/G2 执行；本阶段不触发 CI、签名、发布或设备操作。

## Magi 审查焦点

- Melchior：app 中央 offload 与 plugin 独立入口、target cfg、FFI/selector/DTO、Swift 回调取消、原生库链接、内存硬上限。
- Balthasar：启动权限/更新入口、单一返回栈、Insets 单位、iPad presentation、选择和强渲染；高密度共享界面。
- Casper：先定义可消费的契约，再接 adapter；生成物可重放、签名输入与事实源明确，G1/G2 集中验收。

## 原阶段完成条件

1. 决定、源码、建议、执行结果分开；基线能对应未提交工作树。
2. 命令/授权集合可重跑；隐式 native 通道、未匹配消费者及抽取器限制有明示。
3. 锁定依赖与 Apple 工程输入能定位符号；15.0 的工程取舍和 26+ availability 分层有依据。
4. 产品规范与现行导航一致；Android 原契约保留，iOS 源码审计/Actions 边界明确。
5. 后续问题有阶段、owner 与第一步动作；没有把 Phase 1–6 的实现或 G1/G2 构建伪记为 Phase 0 成果。

本轮不修改业务生产代码；静态检查若作为基线运行，只记录实际结果，不为 unrelated 基线错误扩张范围。文档/工具检查不能证明 Apple 编译、触控几何或调度结果。

后续沿革：Phase 1/2 已完成当时的 cfg、目录、生命周期和原生订阅接入；统一能力表在 2026-10-09 被同步平台身份替代。分享/通知/相机/相册/网络遥测/Distributed 的旧延期已由最新审批覆盖，SSE 后台持续接收进入专项；保留原始 P0 记录不表示维持旧实现方法或范围。
