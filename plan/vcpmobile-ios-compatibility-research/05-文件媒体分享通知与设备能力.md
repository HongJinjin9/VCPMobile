## 当前源码与已批准的实现目标

### 数据目录与 staging

当前路径 owner 已区分平台：Android 的 `get_data_root_dir` 保留 `document_dir().pop()` 推导的原 `files` 位置；iOS 的数据/support 根使用 Application Support，uploads 使用 cache 根。缩略图与派生缓存的所有消费者仍需在 Phase 4 逐条核对，下表区分持久数据、可重建数据和本次导入副本；已有目录函数不表示原生 picker 已接通。

| 数据 | 目标目录 | 规则 |
|---|---|---|
| SQLite、附件 CAS | app data/support | 持久，纳入保护/迁移，使用明确的应用数据目录 |
| 缩略图、多模态派生 | caches | 可重建、可清理 |
| picker/security-scoped 副本、导出中间件 | app cache staging | 有 ticket、大小、TTL、canonical containment |
| 外部 URL | 仅在获取阶段持有 | 在授权窗口内复制，配对 start/stop security-scoped access |

现有 native staging 只接受 `app_cache_dir/uploads` 的直接文件，重算 SHA-256，限制 512 MiB；缩略图使用 `uploads/thumbnails` 的直接文件。该入口由 `register_local_file` 消费。

### 三条现有导入链

```text
HTML < 2 MiB → store_file → 内存 hash + CAS 写入/rename ────────────┐
HTML ≥ 2 MiB → prepare_vcp_upload → XHR/token → stream hash       │
             → finalize_high_speed_upload → CAS ────────────────┤
Native picker → uploads 文件 → register_local_file              │
              → containment/大小/hash 核对 → CAS ────────────────┤
                                                               ↓
                                                register_attachment_internal
```

三条路径共享 CAS 与登记结果。Swift picker 对接 native staging；HTML 两条路径保持各自的字节输入与上传协议。

### P0 原生附件实现

D18 保留 Files Document Picker、PHPicker、security-scoped staging 和 ImageIO 大图/HEIC 处理。HTML 路径可以独立联调；原生路径按下列依赖实施：

1. 主线程呈现 picker，定义成功、取消与 provider 错误 DTO；
2. 在有效的 security-scoped 访问期间协调读取，将外部文件复制到受控 `uploads`，用 `defer` 配对结束访问；
3. PHPicker provider 返回的临时文件在回调生存期内复制，随后由本应用持有新路径；
4. 图片先读取元数据、方向和像素尺寸，按目标像素预算使用 ImageIO 缩略解码，输出受控文件；
5. Swift 返回路径、MIME、尺寸与可选 hash 提示；Rust 重新核验大小/hash，写入 CAS 并登记；
6. 用户取消、provider 失败、复制中断和登记失败分别释放 scope、临时文件与任务引用。

ImageIO 还要连接真正的图片发送入口：`vcp_client.rs` 调 `media_processor/image_extractor.rs::convert_local_image_for_multimodal`，当前该函数仅 Android 调用 `processImage`，其余平台进入 raw fallback。新增 iOS adapter 让 HTML 导入、同步和既存 CAS 图片也经过同一转换；返回受控输出路径、实际 MIME、字节数，并配对清理。Android 当前消费固定写成 `image/webp`，iOS data URL 按真实编码格式构造。

### 文件导出与预览映射

- Rust 长期持有应用自身的 staging/CAS 路径；
- `save_to_downloads` 的用户目标映射到 Files exporter，文件以 URL/ticket 过桥；
- `open_file_native` 的 view 与 share 分开：本地预览接 Swift Quick Look adapter，外部 URL 使用 opener，分享接 `UIActivityViewController`；各自消费真实取消/失败结果；
- iPad presentation 使用触发控件的 popover anchor。

Files 导出、原生预览、outgoing share 和相册保存均进入 Phase 4 实施。当前导出/分享按钮仍仅在 Android 展示；adapter 接通后在原页面恢复 iOS 动作，成功文案使用实际文件名和去向，不能保留“下载/VCPMobile”的 Android 固定路径。文件/图片导入继续作为 P0 优先依赖。

### 当前预算账本

| 路径 | 当前上限/行为 | iOS 动作 |
|---|---|---|
| 普通 IPC 附件 | 前端 `< 2 MiB` 走 IPC；Rust 拒绝 `> 2 MiB` | 等于 2 MiB 时前端走 XHR，保留这项边界用例 |
| HTML 非 GIF 图片 | `> 10 MiB` 或任一边 `> 8192` 拒绝 | 检查浏览器解码与 ImageIO 路径的峰值内存 |
| loopback upload | 200 MiB | token、精确 Content-Length、取消与超时 |
| native staging | 512 MiB | Swift picker 复用同一上限与 hash |
| 文档提取 | 50 MiB 输入；解析完成后截断到 1000 万字符 | 另行核算解析过程的临时缓冲与输出累计 |
| image/audio raw fallback | 严格 `< 5,000,000 bytes` | 图片接 ImageIO 输出预算，语音按 D17 延期 |
| video payload | 18,000,000 字符 | 视觉抽帧延期 |

大上传当前有 30 秒 endpoint 接受窗口、10 分钟连接总期限、10 秒 IO idle 和 16 KiB 请求头上限。前端 XHR 还缺 `abort/onabort`、超时与传输 owner：`removeStaged/clearStaged` 当前只修改 Vue 数组，`input.oncancel` 只处理选择文件取消。实施时把请求句柄、generation 和 staging 清理接到同一次导入的取消路径。

现有 `checkImageDimensions` 通过 `new Image()` 解码获取尺寸，探测失败后继续上传。8192×8192 的 RGBA 单帧约 256 MiB；ImageIO 实现要先取元数据，再按目标尺寸解码，计算源文件、像素缓冲、输出文件与 IPC 的重叠生存期。此处使用静态预算审查，沿用 D16 的性能范围。

### 相机、照片与语音

当前 iOS 文件/图片仍可走 HTML 导入；原生拍摄与相册保存入口尚未开放。语音按钮已保留，点击说明尚未开发，不请求麦克风；Android 录制/Whisper 链仍存在，录制 MIME 与固定 `.webm` 文件名的契约问题需在语音专项处理。

实施范围：

- 文件/照片导入：进入 P0，按上述原生路径实现；
- 相机与 PhotoKit 保存：已批准，在 P4-2 接入；权限请求、取消、拍摄方向/编码、写入结果和临时文件清理一起完成；
- 录音/语音：D17 的尚未开发范围继续保留，入口提供说明；后续接入先修复 MIME/扩展名契约；
- 视频作为普通附件可保留，视觉抽帧延期。

语音的源码发现是 MIME 与固定 `.webm` 文件名不一致；这是后续修复项，D17 本身作为产品范围决定继续保留。

### Share 当前事实

- Outgoing share 已被 Android 同步日志等路径消费；iOS 插件当前返回不可用，不落入 host 空成功分支；
- Incoming share 的 Vue session、generation、`register_shared_files` 与会话预填 owner 已存在，缺的是 iOS native producer；
- incoming/outgoing share 已获批准，原 D9 延期被覆盖，分别由 P4-4/P4-3 接入；
- incoming producer 复用现有 session/generation/ticket，外部文本与附件交给主 App 的同一导入 owner，处理冷启动、已运行、重复交接和用户取消；
- P4-4 先确定 Share Extension 的获取/交接方式及其生成输入，核对用户自签可提供的 App Group/profile 条件；不复制 Chat/CAS owner，也不假定所有自签环境都具备同一 entitlement。最终 Bundle ID、扩展 ID、共享容器和嵌套签名输入纳入 Phase 6 打包说明。

### 通知与剪贴板

本 App 系统通知 P3-3 源码已接入：Swift 提交真实本地通知，启动前安装 UN delegate，并从 Scene connection options 接冷启动点击；latest snapshot 与实时事件归同一前端消费者。App 内通知中心/Toast 继续保留；尚无 Apple 运行结果，不包含 APNs 服务端、付费 Team 或完整推送架构：

- 共同权限引导使用实际通知授权状态；原生请求按用户动作发起，拒绝不阻断普通聊天；
- 对本 App 的本地通知建立发送结果、前台展示及点击响应；冷启动待取响应和运行期响应汇入同一导航 owner，避免重复消费；
- 跨 App notification listener 归 Android 功能面。

普通 UI clipboard 写入由用户动作触发，保持现有共享路径。Distributed clipboard 的 P3-5 iOS 操作已接 `UIPasteboard`，仅在实际前台读取/写入，保留用户逐工具授权；读取结果与无法访问的原因交给现有工具结果消费者。

### 共同权限引导

P3-2 已在共同外壳接入本 App 通知权限；定位/运动权限由实际工具采样请求。不把 `check_all_permissions` 或 Android 通知监听、OEM 自启动、电池豁免翻译为不存在的 iOS 开关。通知授权在请求后和设置返回后刷新，未询问、拒绝或有限状态按实际消费表达，不新增静态四字段总表。

P3-4 已接可用空间与应用所在卷的总量查询，不表示 sandbox 配额，也不增加 iOS 的 5 GB 启动阻断。电量/低电量模式进入 Sync，未知首读与实际 0 分开，其他设备数据由工具消费。

### 设备事实与 Distributed

| 能力 | iOS 映射 |
|---|---|
| 屏幕常亮 | P5-4 接前台 idle timer，按活动任务持有并恢复原状态 |
| 电池 | P3-4 已接 level/state + Low Power；首次读数与温度缺失如实表达，Sync 消费真实结果 |
| thermal | `ProcessInfo.thermalState` 系统热压力 |

P3-5 已接 iOS client、registry、显式 enabled-tool allowlist 与 telemetry owner，设备/网络/通知/剪贴板/传感器和聚合沿原执行路径消费；进入后台停止节点，回前台按配置恢复，不占用尚未实现的 SSE 后台资源。没有 API、权限或字段时报告具体缺失，不伪造零值、不关闭整个节点；Android CLI/Root 等原生机制没有 iOS 实现。具体源码复审与本地验证见 Phase 3，Apple 原生运行仍未验证。

### WebView 缓存

当前共享设置页已保留缓存入口，iOS 点击说明 WebKit 清理尚未接入，预渲染/数据库维护仍走各自 owner。P4-5 接入 WebKit HTTP/浏览缓存的实际清理 API，先明确数据类别与时间范围，排除用户业务数据；按结果报告清理完成或失败，不虚构已释放字节数。按钮说明、处理中状态和完成提示一并更新。

## 完成条件

P0 文件/图片输入均能追踪到 CAS 登记；正常、取消、provider 错误、超限与 hash 不符都有确定结果。逐条核对安全作用域、临时文件、上传句柄、像素缓冲的创建和释放。检查用例记录尺寸、字节数、MIME、方向、导入入口和预期结果，沿每条输入链演算资源预算、错误消费与清理终态。

已批准的权限引导、通知、设备/网络与 Distributed 在 P3-2–P3-5 分别有实际消费者；相机、相册保存、导出/预览、双向分享和 WebKit 缓存在 P4-2–P4-5 闭合。阶段记录分别标注已批准、源码已实现及 Apple 构建证据，不将本文映射表当成完成证明；阶段性检查统一按 07 执行。
