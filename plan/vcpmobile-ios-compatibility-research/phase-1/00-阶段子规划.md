# Phase 1：平台能力与共享契约子规划

> 2026-10-08 启动并完成。基线提交 `489b3341`，结果见 [验收与交接](./07-验收与Phase2交接.md)。产品输入沿用 D1–D19；当前源码决定调用关系，本文记录本阶段施工与边界。

## 目标与边界

建立由 Rust 提供、启动 owner 先读取的 typed `PlatformCapabilities`；同时闭合 UI、直接调用、Rust 原生副作用和 ACL。保留 Android 现有实现与持久目录。iOS 尚未接入 Swift 的能力明确为未实现，不进入 host 模拟成功分支。

Phase 2 接 Swift/Scene/native Channel；Phase 3 接业务收尾；Phase 4 接原生附件和 WebKit；本阶段不伪造这些完成状态，不执行 Apple 构建、设备操作或发布。前端运行时能力开关不等于构建裁剪；平台原生实现与依赖仍使用编译条件隔离。

## Magi 开工审查

- **Melchior**：native sequence 不能替代 Rust transition epoch；原生事件回放与 live event 必须在唯一 owner 排序。iOS 不允许落入 host 固定电量/权限全真/no-op 成功。plugin IPC 与 app IPC 分别收口。
- **Balthasar**：能力未知时不闪现 Android 引导/更新；失败有可重试状态。根返回沿 modal/page/session 既有 owner，iOS 根保持应用。隐藏入口必须与调用门禁同步，应用内通知不随系统通知能力一起关闭。
- **Casper**：不复制页面、业务 store、目录注册器或领域终态；用现有 owner 加明确边界。保持 Android API 和数据根，不借适配搬迁历史数据。将 Swift、原生附件、后台执行的未完成工作准确交给后续阶段。

## 完成条件

1. 能力查询、Rust/TS 字段、UI/direct 调用、插件错误与 ACL 一致。
2. Android 既有数据目录和消费者保持；iOS 原生占位返回明确错误。
3. 生命周期真实 snapshot/live 输入可排序，重复/迟到消息不会覆盖新状态；清理不被入口门禁阻断。
4. `pnpm check`、必要的字段/重试/事件/路径测试及 Kotlin 定向检查完成，实际结果写入验收记录。
5. 审查本阶段 diff，保留继承的 package/lock/build 与六个 permission 文件修改；不自动提交、不 push。

阶段状态与后续输入以验收记录为准；源码检查、host 编译和 Apple 构建证据分别记录。
