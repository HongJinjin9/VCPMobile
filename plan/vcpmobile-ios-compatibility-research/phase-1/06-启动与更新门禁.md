# Phase 1：启动与更新门禁

> 2026-10-08 源码实施记录。沿现有 Vue 启动与 Rust 更新状态所有者接入平台能力；未接入 Swift，也未取得 Apple 构建或运行结果。

## 1. 起点、所有者与实施范围

Phase 0 发现 `appLifecycle.bootstrap` 无条件检查 Android 通知、电池优化与通知监听，`App.vue` 创建 `useAutoUpdate` 时立即初始化 APK 更新，关于页、下载通知、根返回与系统分享入口也缺少平台选择。当前能力输入来自共享 `get_platform_capabilities` 命令，由 `usePlatformStore` 保存进程级快照，启动 owner 负责首次加载。

`isImplemented(name)` 只说明平台支持且存在实现，不等价于用户授权或本次原生操作成功。Android 的权限查询、安装器与下载命令继续返回各自真实结果；未加载、平台不支持与尚未实现分别报错。

| 生产位置 / owner | 本阶段结果 | 失败、重复与释放 |
|---|---|---|
| [`appLifecycle.ts`](../../../src/core/stores/appLifecycle.ts) | `bootstrap` 先加载平台能力；只有 `androidPermissionGate` 有实现才执行原有权限检查。能力失败进入 ERROR，保持启动屏；成功后沿原快照、核心就绪、业务预加载到 READY | 复用已有启动 Promise；能力查询失败可由同一 `bootstrap(true)` 重试。Android 权限查询本身失败仍保留原来的前台降级与明确后台警告，iOS 不产生该警告 |
| [`BootScreen.vue`](../../../src/components/layout/BootScreen.vue) | 能力读取失败或非 Android 启动失败，按钮重新调用启动 owner；Android 已确认平台后的核心错误继续走既有重启命令 | `try/finally` 释放重试锁；iOS 按钮不执行 Android 重启/退出命令 |
| [`PermissionGate.vue`](../../../src/components/layout/PermissionGate.vue) | 组件挂载和权限轮询、查询、申请、退出动作均检查对应能力；Android 三步引导保持 | 不因 iOS 无实现生成全 true 的权限对象；原 visibility/权限事件/低频轮询的卸载释放保持 |
| [`App.vue`](../../../src/App.vue) | PermissionGate、分享选择器、UpdatePrompt 按能力挂载；系统分享文件登记和通知导航消费也检查能力；冷启动通知只在 READY 且能力存在后读取一次 | 同步 DOM 监听继续尽早建立，已有 share operation / notification generation 与 READY 等待保留；能力错误后重试不需要建立第二套意图队列。冷通知迟到结果在卸载后丢弃 |
| `App.vue::handleExitRequest` | 仍先关闭最上层 modal，再清空当前会话；根部只有 `moveTaskToBack` 实现存在才展示双击退出提示和调用 Android 后台动作 | iOS 根部保持应用；Android 的原生动作失败仍保留原窗口关闭 fallback。退出计时器在卸载时清理 |
| [`update.ts`](../../../src/core/stores/update.ts) | 初始化、检查、下载、取消、安装和打开 Prompt 全部要求 `apkUpdate`；继续镜像 Rust UpdateSession 的快照 | 初始化同 flight 复用；订阅/快照失败可重试，失败快照对应订阅立即释放；Pinia scope 销毁时释放订阅，迟到订阅也释放 |
| [`useAutoUpdate.ts`](../../../src/core/composables/useAutoUpdate.ts) | 平台能力明确后才初始化更新状态；READY 后两秒才检查；执行时再次确认能力与 READY | 保留原 24 小时冷却、跳过版本与自动检查开关；状态离开 READY、能力不可用或 scope 销毁时清理未执行计时器 |
| [`useUpdateDownloader.ts`](../../../src/core/composables/useUpdateDownloader.ts) | 下载入口先要求 APK 能力，系统进度通知由 `systemNotifications` 控制，移除该链 UA 判断 | 通知拒绝不阻断 Android APK 下载；现有状态 watcher、通知撤销和错误反馈保留 |
| [`AboutSection.vue`](../../../src/features/settings/components/AboutSection.vue)、[`UpdateSection.vue`](../../../src/features/settings/components/UpdateSection.vue)、[`UpdatePrompt.vue`](../../../src/components/ui/UpdatePrompt.vue) | 关于页版本信息独立保留；APK 更新区域、状态初始化与系统安装授权动作由能力封闭 | 初始化异常记录并允许手动检查重试；iOS 不出现检查 APK 或安装按钮 |

生命周期代理提供的 `LifecycleSnapshotDto`、`selectLatestLifecycleSnapshot` 同步接入启动 store：系统快照补齐同一生命周期状态，`isBackground` 从该状态派生。该 DTO 和事件订阅的完整语义见本阶段生命周期记录。Insets 单位与 WebKit 适配仍由 Phase 4 处理，本批未改写现有 Insets 桥。

## 2. Balthasar 交互裁决

- 能力未知时显示读取状态，失败显示真实启动错误并提供重试；不先闪出 Android 引导，再依赖调用失败隐藏。
- APK 行为区域与版本信息分离；App 内通知中心继续保留，不与系统通知权限绑定。
- 根返回保留现有 modal / session 所有权，iOS 根部不展示双击退出提示。
- 原生分享与系统通知继续复用已有意图身份、READY 等待和导航消费链，不建立第二个导航 Store。
- Android 权限检查异常的现有前台降级，与平台能力查询失败的启动阻断是不同语义；不得合并成“未知即成功”。

## 4. 后续阶段输入

1. Phase 2 接入真实 iOS adapter 时，按已存在的能力字段逐项开放实现，不将所有 `notImplemented` 一次改成成功。
2. Phase 3 继续检查核心 ERROR 的恢复原因、READY 路径与共享业务启动；本批没有增加一个新的 Rust 核心重启器。
3. Phase 4 接 Files/PHPicker 与 UIKit Insets 后，分享导入与系统通知仍保持首期延期决定；不能用文件选择器实现反向打开 incoming share。
4. iOS 自签产物的分发属于 Phase 6，继续独立于 Android APK updater。
