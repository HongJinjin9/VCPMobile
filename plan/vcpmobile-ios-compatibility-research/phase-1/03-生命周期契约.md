# Phase 1：生命周期 DTO 与唯一状态所有者

2026-10-08 Phase 1（基线 `489b3341`）把 Android Channel、Rust lifecycle owner 和 Vue 连成有序契约。2026-10-09 校准：Swift producer/Scene 已由 Phase 2 接入，iOS 业务收尾仍归 Phase 3；原验证保留在第 5 节，不把它写成当前 Apple 执行结果。

## 1. 字段与状态来源

原生 `lifecycle` 事件的 `payload`：

```json
{
  "phase": "active",
  "nativeSequence": 8,
  "snapshot": false
}
```

| 字段 | 类型 | 来源与语义 |
|---|---|---|
| `phase` | `active / inactive / background` | 原生应用状态。Android 保留 ProcessLifecycleOwner 规则；Phase 2 Swift 已区分 active/inactive/background |
| `nativeSequence` | 非负整数 | 原生进程事件源每次有效迁移递增；Android 使用进程级计数器，插件实例替换不重置；首次无迁移快照允许 0 |
| `snapshot` | boolean | Channel 注册回放为 true，后续实时事件为 false；不是新的业务迁移，也不会延长后台计时器 |

Rust 输出的 `LifecycleSnapshot` 增加 `transitionEpoch`，并允许 host 开发来源的 `nativeSequence` 为 null。epoch 来自现有 Rust transition owner；它与原生计数器具有不同的作用域，不能互相比较或用原生 sequence 替换 Rust epoch。

`get_system_snapshot.lifecycle` 是 `LifecycleSnapshot | null`。收到真实来源前为 null，不能根据旧 `is_foreground` 默认值构造一个“iOS 已 active”的结果。读取系统快照时标记 `snapshot: true`，保留已经应用的 phase、sequence 与 epoch。

## 2. 当前生产调用链

1. [`LifecycleBridge.kt`](../../../src-tauri/plugins/vcp-mobile/android/src/main/java/com/vcp/mobile/LifecycleBridge.kt) 在 Android 进程生命周期回调中生成 phase、sequence；`snapshot()` 提供注册回放。configuration/memory-pressure 使用独立事件名，不能混入必需字段完整的 lifecycle 载荷。
2. `VcpMobilePlugin.registerNativeEvents` 沿用原有主线程串行注册、快照和实时 Channel；无需新建第二个订阅者。
3. [`events.rs`](../../../src-tauri/plugins/vcp-mobile/src/events.rs) 强类型解码为 `NativeLifecycleEvent`。缺失 sequence、非法 phase 或负 sequence 报解码错误；非生命周期/网络事件不进入业务迁移。
4. [`lifecycle_manager.rs`](../../../src-tauri/src/vcp_modules/infra/lifecycle_manager.rs) 的 mobile Channel 回调交给 [`lifecycle_controller.rs`](../../../src-tauri/src/vcp_modules/infra/lifecycle_controller.rs)；Phase 2 已加入 iOS producer，callback 保持短时排序与排队。
5. controller 先在同一短锁内拒绝重复/旧 native sequence，再保留 Rust epoch；工作任务使用已有 transition 单锁。过期 epoch 在执行前退出，已经开始的 Android transition 保持原有完整收尾语义。
6. [`LifecycleState`](../../../src-tauri/src/vcp_modules/infra/lifecycle_state.rs) 保存已经应用的快照；controller 发出 typed `vcp-lifecycle-changed`，`get_system_snapshot` 提供迟到消费者的回放。
7. [`useAppLifecycle.ts`](../../../src/core/composables/useAppLifecycle.ts) 先订阅，再读取系统快照；[`appLifecycle.ts`](../../../src/core/stores/appLifecycle.ts) 用 [`lifecycle.ts`](../../../src/core/types/lifecycle.ts) 的 epoch 归约为同一个 `lifecycleSnapshot`。`isBackground` 由 phase 派生；document.hidden 仅影响动画和当前页面恢复时机，不覆盖原生 phase。

无生产前端消费者的 `set_app_foreground_state` IPC 入口移除；host `WindowEvent::Focused` 仍使用 Rust 内部 epoch 函数，开发窗口事件不成为移动端业务入口。

## 3. 竞争与 Android 行为

| 输入顺序 | 归约结果 |
|---|---|
| 首次 native snapshot sequence=0 | 接受。未收到事件与 sequence=0 是不同状态 |
| active(8) → background(9) → 延迟 active(8) | 旧 native 事件在保留 epoch 前丢弃，不能反过来淘汰 background 工作任务 |
| background(9) → 重复 snapshot(9) | 不建立新的后台区间，不重置已有 linger token 或计时器 |
| native callback 先到，但工作任务执行顺序颠倒 | 原有 epoch 规则跳过尚未开始的过期任务；已开始的迁移持锁完成 |
| Vue 先收到 background epoch=2，后收到旧系统快照 active epoch=1 | 前端保持 background；snapshot 标志不能绕过排序 |
| inactive | 保存并广播 phase、暂停动画；不因暂时失焦申请 Android 后台租约，不执行前后台业务切换 |
| WebView 异步注册监听期间卸载 | 注册完成后立即释放该监听，避免留下迟到根监听 |

Android 的 VCPLog 10 分钟 linger、Distributed 5 分钟 linger、租约释放和恢复意图仍由原有 controller 持有。Phase 1 为 iOS 排除这组 Android 租约/计时器；不在 DTO 施工中另写 iOS Chat/Sync 的停止或重试策略。

READY、online、回前台的 Android interrupted-stream 对账入口保留；inactive/background 时不触发前台对账，浏览器恢复可见时再检查当前权威 phase。没有第二条业务请求或复制的终态状态。

## 4. 当前平台分支与后续业务接入

- 统一 `Distributed` capability 和重复 Rust 门禁已删除。当前节点原生运行仍只有 Android，用户可在 iOS 浏览目录/保存配置；设置值、有效连接参数和实际运行结果继续归原 owner。
- Phase 3 按已批准方向接 Distributed，逐工具处理真实权限和字段，不能把任一缺项扩大为整个节点不兼容。
- iOS 的 `restart_or_exit_app` 返回不支持，不继承 host 进程退出路径。
- Swift producer、`events::subscribe`、bootstrap 和 Vue 已接通；同步 `isIOS` 只选择首次 active 条件，不替代 phase/epoch 真实观测。
- Phase 3 将 background 接到有界 cancel/stop/join/flush；Phase 5 研究 SSE 持续接收及其余尽力后台并绑定同一任务。源码接通不表示 G1 编译或 iOS 回调运行已经验证。
