# Phase 1：功能入口与能力消费

> 2026-10-08。本文记录本阶段已修改的前端入口；启动、权限引导与 APK 更新由本工作区独立记录。平台事实来自 Rust `get_platform_capabilities`，前端不以 UA 或已有设置推断原生实现。

## 1. 共同契约与边界

[`platform.ts`](../../../src/core/stores/platform.ts) 是进程级能力快照消费者，启动 owner 先加载。`isImplemented(name)` 只判断支持范围与已有实现；`require(name)` 拒绝未知、范围外或尚未实现的调用。授权与运行状态是独立字段，进入已实现路径后仍由原有命令检查权限、报告错误，不能把这个门禁解释为授权成功。

前端入口选择不能代替 Rust command/cfg 与 ACL 边界。直接 IPC 的拒绝由后端负责；组件不增加另一套业务 owner。已有 Android 状态、操作 identity、generation、取消和清理流程继续使用原位置。

## 2. 文件级闭环

| 路径 / owner | 已实施门禁 | 保留的结果与异常语义 |
|---|---|---|
| `RightSidebar.vue` | CLI 工具与插件中心按 `cli` / `distributed` 展示 | 日记、App 内通知、其余共享页面保持 |
| `overlay.ts::pushPage` | 拒绝不可用的 `cliManifest` / `distributed`，覆盖公开导航方法 | 不创建页面栈项与返回历史；不另建平台页面栈 |
| `FeatureOverlays.vue` | CLI、Distributed 挂载同时检查能力；`ToolInteractionOverlay` 必须能力可用且设置开启 | 导入 Android 设置中的 `distributedEnabled=true` 不足以在 iOS 挂载监听器 |
| `DistributedView.vue` / `useDistributed.ts` | 页面 open、status 订阅/查询与 Root 查询/启动分别使用 `distributed` / `rootAccess` | Android 监听引用计数与过期 snapshot 检查保持；release/deactivate 不被门禁阻断 |
| `vcpCliStore.ts` | status/action 和原生技能导入/提交前检查 `cli`；picker 另查 `filePicker` | 错误归入现有 runtime/skill 错误状态；Android operation ID、轮询、取消、discard 清理继续由原 owner 管理 |
| `InputEnhancer.vue` | 录音/STT 按钮与开始手势检查 `voiceRecording`；相机按钮检查 `camera` | 同一输入组件树，文本/群聊/附件/发送不复制实现 |
| `useAudioRecorder.ts` / `useSpeechRecognition.ts` | 开始录音/识别前 `require('voiceRecording')`；Android 权限请求使用 typed platform | 即使绕过按钮也不在 iOS 请求麦克风或调用 Web Speech/getUserMedia；既有 stop/cancel 仍可释放资源 |
| `attachmentStore.ts` | native file/photo picker 按能力选择，相机调用独立检查；移除 Android UA 判断 | 文件/图片继续允许已有 HTML 子路径。它不代表 Files/PHPicker 已实现，也不替代 Phase 4 P0 原生导入 |
| `AgentSettingsView.vue` / `GroupSettingsView.vue` / `UserProfileSection.vue` | 调用 `pickFile('avatar')` 前检查 `photoPicker` | 现有头像仍显示；不可用时复用头像错误提示，不创建临时工作副本；旧的裁剪副本清理不被阻断 |
| `AttachmentPreview.vue` / `AttachmentViewer.vue` | 外部打开用 `fileOpen`；保存到相册用 `gallerySave`，包括截断文本工具条的入口与文案 | 本地图片/文本预览保留；不把外部打开和本地查看混成一个开关；不可预览二进制的直接点击由现有错误提示说明 |
| `MermaidFullScreenViewer.vue` | `gallerySave` 控制导出入口与操作 | SVG 源码/复制/本地渲染保留，不因保存延期削弱强渲染能力 |
| `SyncLogBrowserCore.vue` | `outgoingShare` 控制分享按钮，并在创建分享临时文件前检查 | 查看、复制、清理日志保留；不先生成无消费方文件 |
| `ConfigBackupSection.vue` / `useConfigBackup.ts` | `fileExport` 控制导出按钮和 IO；storage 权限重试明确仅 Android | HTML `.vcpcfg` 导入与白名单解析保留；配置恢复不修改原存储的 Android 字段来冒充关闭业务 |
| `MailDetailView.vue` / `mailStore.ts::downloadAttachment` | 附件导出按钮与下载函数使用 `fileExport`；检查位于 `mail_attachment` 远程下载与 Base64 接收之前 | 收信、正文读取、附件名称/类型/大小展示保留；不因不能导出而禁用共享邮件读取 |
| `MaintenanceSection.vue` | WebView 缓存按钮与 IO 用 `webviewCache` | 共享预渲染/数据库维护入口保留，不因 native 缓存不可用一并隐藏 |
| `syncSession.ts` | 电量读取前检查 `batteryStatus`，缺失走现有无法确认的 warning 分支 | Android 省电模式和低于 30% 电量仍阻断；读取失败原有 warning-and-continue 保留，不制造正常电量 DTO |

Android 能力已实现并不保证每次操作成功。权限拒绝、Root 不可用、picker 取消、IO 错误仍由相应原生或领域调用返回；门禁不吞掉这些结果。

## 3. 手动 Sync 的特殊约束

现有 `beginSync` 在第一个 await 前锁定页面；listener 注册后读取 battery，再调用 `start_manual_sync`，每次 await 后比较 attempt 与 view generation。本阶段仅在 battery 调用前增加能力检查，保留这条时序和业务阈值。

Phase 1 的 iOS 尚无真实 battery adapter，因此日志准确记为“无法确认设备状态，将继续同步”，不会发送一个注定不可用的 native 查询，也不会打印“设备状态检查完成”。Phase 2/3 接入真实最小电量/低电量模式数据后，再由同一消费者执行已有判断。完整设备遥测延期不等于永久删除这项依赖。

## 4. Magi 结论

- **Melchior：** UI 隐藏、Store 前置检查、Rust 拒绝与 ACL 分工明确；清理入口继续可达，避免能力状态变化使已有资源无法释放。
- **Balthasar：** iOS 不出现 CLI、插件中心、录音、相机、系统分享或相册保存的无效入口；现有头像和消息预览不消失，点击暂不可用的头像修改能获得明确错误。
- **Casper：** 直接修改已有入口与 owner，不新增命令代理层、平台页面树或复制业务状态。HTML 导入与原生 P0 实现分别记录，避免把中间联调子路径当成最终产品完成。

## 5. 验证与后续工作

定向验证覆盖 CLI 三组、Distributed 两组、SyncSessionConcurrency 与配置备份纯函数，共 7 个测试文件。已有功能测试显式初始化 Android capability，使用真实 platform store；通用 mount helper 的可选初始化参数不改变其他测试的默认平台。

新增断言覆盖 iOS 不发送 CLI status/action、Distributed 不订阅/查询、battery 尚未实现时警告并沿原业务继续，以及 Android 低电量/省电模式继续阻断。完整执行结果见本阶段验收记录；测试输入用于说明这次执行，不反向定义产品能力。

补充审查追踪了邮件详情唯一导出消费者：`MailDetailView.download` → `mailStore.downloadAttachment` → `mail_attachment` → guest `saveToDownloads`。邮件定向测试验证 Android 仍下载并导出、iOS 在下载前拒绝，同时两端都能读取正文与附件元数据。该检查仅限制导出路径，不限制共享收信。

本阶段未取得 Apple 构建或 iOS 运行结果。Phase 4 仍需原生 Files/PHPicker、头像工作副本、文件打开/导出、staging/取消与大图处理；系统分享、相册保存、相机与语音仍按已定产品边界延期。HTML 导入原有 XHR/迟到回执等资源治理由其阶段完成。
