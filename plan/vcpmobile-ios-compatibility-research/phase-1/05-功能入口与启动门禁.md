> 历史实施：2026-10-08 Phase 1，施工基线 `489b3341`。2026-10-09 已移除能力查询/Store/类型；本文件保留当时入口修改与验证，当前后续工作见第 5 节。不能把旧隐藏/延期策略当作最新产品决定。

## 1. 原共同契约与后续替代

原 `src/core/stores/platform.ts` 曾由启动 owner 加载，再用 `isImplemented/require` 选择入口；该历史文件已删除，不再提供有效源码链接。当前统一入口为 [`src/core/utils/platform.ts`](../../../src/core/utils/platform.ts)，同步导出 OS 身份，Vue 按真实功能直接分支。授权/运行状态由实际操作取得，不汇总成四轴表。

已有 Android 状态、操作 identity、generation、取消和清理仍使用原 owner；编译隔离和框架授权按实际调用配置。当前不以防范绕过 UI 为理由在 Rust 重复功能门禁，也不建立每按钮适配器。

## 3. 手动 Sync 的特殊约束

现有 `beginSync` 在第一个 await 前锁定页面；listener 注册后读取 battery，再调用 `start_manual_sync`，每次 await 后比较 attempt 与 view generation。本阶段仅在 battery 调用前增加能力检查，保留这条时序和业务阈值。

Phase 1 的 iOS 尚无真实 battery adapter，因此日志准确记为“无法确认设备状态，将继续同步”，不会发送一个注定不可用的 native 查询，也不会打印“设备状态检查完成”。Phase 2/3 接入真实最小电量/低电量模式数据后，再由同一消费者执行已有判断。完整设备遥测延期不等于永久删除这项依赖。

## 4. 原阶段 Magi 结论

以下为当时判断；统一门禁与全量隐藏意见已被最新审批及跨平台规范替代，共享 owner 和原生附件证据边界继续保留。

- **Melchior：** UI 隐藏、Store 前置检查、Rust 拒绝与 ACL 分工明确；清理入口继续可达，避免能力状态变化使已有资源无法释放。
- **Balthasar：** iOS 不出现 CLI、插件中心、录音、相机、系统分享或相册保存的无效入口；现有头像和消息预览不消失，点击暂不可用的头像修改能获得明确错误。
- **Casper：** 直接修改已有入口与 owner，不新增命令代理层、平台页面树或复制业务状态。HTML 导入与原生 P0 实现分别记录，避免把中间联调子路径当成最终产品完成。

## 5. 历史验证与当前后续工作

2026-10-08 定向验证覆盖 CLI 三组、Distributed 两组、SyncSessionConcurrency 与配置备份纯函数，共 7 个测试文件。当时使用 capability fixture 和真实 platform Store；该模型及测试入口已随平台简化替换，旧断言不反向约束生产实现。

新增断言覆盖 iOS 不发送 CLI status/action、Distributed 不订阅/查询、battery 尚未实现时警告并沿原业务继续，以及 Android 低电量/省电模式继续阻断。完整执行结果见本阶段验收记录；测试输入用于说明这次执行，不反向定义产品能力。

补充审查追踪了邮件详情唯一导出消费者：`MailDetailView.download` → `mailStore.downloadAttachment` → `mail_attachment` → guest `saveToDownloads`。邮件定向测试验证 Android 仍下载并导出、iOS 在下载前拒绝，同时两端都能读取正文与附件元数据。该检查仅限制导出路径，不限制共享收信。

当前仍无 Apple 构建或 iOS 运行结果。Phase 3 接共同权限、本 App 系统通知及设备/Distributed；Phase 4 接 Files/PHPicker、头像/图片处理、打开/导出、拍照、相册保存、双向分享及 WebKit，原旧延期已撤销。语音仍未开发，当前入口可说明后返回；HTML 导入 XHR/迟到回执和临时副本治理继续归 Phase 4。
