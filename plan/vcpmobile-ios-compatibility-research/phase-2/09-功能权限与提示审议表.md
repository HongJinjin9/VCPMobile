# iOS 功能权限与提示审议表

> 2026-10-08，基线 `cd16274a`。用于用户审查保留、重构、暂缓及告知方式。下文“当前”来自生产代码；“建议”尚未写入产品；已有 D1–D19 继续有效。本轮没有改变功能范围、权限或界面。

**当前 iOS 是原生接入中的版本。** 24 项能力中，1 项标记已实现、10 项计划支持但尚未实现、13 项标记 unsupported。后者同时包含 Android 专属机制和已决定延期的功能，不能解释成“iOS 系统全都做不到”。网络连通 Channel 已接入，但不等于完整网络遥测已实现。源码接入尚没有 G1 Apple 编译结果。

## 1. 已决定的产品方向

- **保留并适配：**同一 Vue/Rust 核心、iPhone+iPad 单 Scene、文档/文本/图片、原生文件链、安全区与键盘、受信 LAN、常亮及 iOS 26+ 尽力后台。对应 D1/D2/D5/D7/D11/D12/D15/D18/D19。
- **改变平台语义：**Android 下载目录改为 Files 导出；Android 前台服务改为有界任务；Android 根返回退后台改为 iOS 页内返回；APK 自动更新改为 App 外用户自签安装。后者 D8 已确定。
- **明确延期：**incoming share（D9）、系统通知/APNs（D10）、语音（D17）；以及既有范围中的相机、相册保存、向外分享、视频抽帧、完整遥测/Distributed。
- **保留 Android 专属路径：**Root、APK 安装/未知来源设置、OEM 自启动/电池豁免、通知监听、Android CLI/PTY 等，不为 iOS 伪造同名成功接口。

这些是历史已决定的基线，列出供本轮逐项审查。用户正在审议能力范围；新的范围与告知选择尚待用户决定，本轮不据此落地。下面提供当前缺失和告知方案。

## 2. 24 项能力按用户场景说明

### 已接入的原生事实

| 功能 / capability | 当前情况 | 保留和提示建议 |
|---|---|---|
| 生命周期 `lifecycle` | Swift App/Scene → Channel → Rust phase/epoch → Vue；唯一实现态能力；G1 未执行 | 保留；先补单 Scene 恢复和订阅异常提示，见 08 的 R2/R3 |

额外的 NWPath 连通事件已为同一恢复流程提供“可以再试一次”的线索；不代表互联网、服务器或局域网已获准且可达，也不是下面的 `networkStatus` 遥测。

### 计划保留，但需要原生适配或平台重构

| 功能 / capability | Android 用途 | iOS 当前入口与行为 | 实施方向 |
|---|---|---|---|
| 安全区/键盘 `nativeInsets` | 原生 Insets 事件驱动共享 CSS | 尚无 iOS adapter；仍有共享 CSS/键盘 fallback | Phase 4，不能把 Scene 接通当作触控/键盘适配完成 |
| 文件选择 `filePicker` | 系统选文件、staging、hash、CAS | 原生未接；聊天可走 HTML 文件输入 | D18 P0，接 Files/security scope/staging，并保留真实取消/失败结果 |
| 图片选择/头像 `photoPicker` | 选图、工作副本、裁剪头像 | 聊天可走 HTML；用户/Agent/群头像入口仍可点击，随后报未适配 | D18 P0，接 PHPicker/图片处理；过渡期明确说明头像选图尚未接入 |
| 文件导出 `fileExport` | 配置、邮件附件等写公共下载目录 | 配置导出、邮件附件导出入口隐藏；配置 HTML 导入保留 | 改成用户选择 Files 目的地；成功提示使用实际结果，不写死“下载/VCPMobile” |
| 文件打开 `fileOpen` | 外部 App 打开 PDF/办公文档/音视频 | Viewer 外部打开按钮隐藏；直接点部分非图片/文本附件仍会触发未适配错误 | 适配原生打开/预览；保留附件，不把不可预览误说成文件损坏 |
| 最小电量/省电信息 `batteryStatus` | 手动同步预检 | 未查询模拟电量；日志提示“无法确认设备状态，将继续同步” | 根据同步实际需求迁移最小字段；完整设备遥测延期不等于删除此消费者 |
| 可用空间 `diskSpace` | Android 权限页容量及 5 GB 门槛 | 未实现；iOS 不挂该权限页，因此没有同样启动阻断 | 按容器和实际操作预算使用，不照搬 Android 5 GB 门禁 |
| 前台常亮 `keepScreenOn` | set/clear 插件接口 | 未实现，当前不能声称已有常亮回退 | D2 的回退要求；绑定实际任务 owner，结束/取消时释放 |
| 后台执行 `backgroundExecution` | 前台服务、租约、WakeLock/helper | iOS foreground 接口未实现，Android service 路径拒绝 | D2/D15，Phase 3 先闭合业务收尾、Phase 5 接尽力后台，不能把后台保证写成 Android 等价 |
| WebView HTTP 缓存 `webviewCache` | 设置页清 HTTP 缓存 | 按钮隐藏；共享数据库/渲染缓存维护仍存在 | 接 iOS 缓存 owner；不要宣传“所有缓存维护都不可用” |

这里的 10 项均为 `supported + notImplemented`。所谓“计划保留”不是当前可用承诺；`implementation`、授权状态和实时可用性是不同字段。

### 当前不提供，区分 Android 机制与既定延期

| 功能 / capability | Android 用途 | iOS 当前行为 | 范围归属及说明 |
|---|---|---|---|
| 启动权限页 `androidPermissionGate` | 通知、电池优化豁免、通知访问等 | 启动跳过 Android 检查，不挂载 Gate | Android 专属引导；iOS 未来按实际操作请求权限 |
| APK 更新 `apkUpdate` | 下载、签名检查、未知来源安装、OTA 保活/通知 | 更新入口、自动检查、覆盖层隐藏；后端也拒绝 | Android 专属；iOS 自签安装在 App 外，D8 |
| 根返回退后台 `moveTaskToBack` | Android task 退后台 | 页面/覆盖层正常逐层返回，到根停留 | 平台行为不同，无需模拟 Android 退出方式 |
| Root `rootAccess` | Root 检测、执行及管理器 | Distributed 页面隐藏，后端拒绝 | Android 专属；不引入越狱能力 |
| 本地 CLI `cli` | Android CLI/PTY/运行时与技能管理 | 侧栏和页面隐藏，Store/后端均拒绝 | 当前 Android 运行时不迁移；未来远程终端应作为新产品需求 |
| 接收系统分享 `incomingShare` | 其他 App 分享文字/附件到 Agent | 分享接收入口与选择器不挂载 | D9 已延期；不是服务器附件同步也被取消 |
| 系统通知 `systemNotifications` | 本 App 通知、点击导航、系统下载状态 | 原生通知入口不接；App 内通知中心/Toast 保留 | D10 已延期；与 Android“读取其他 App 通知”的权限另作区分 |
| 语音 `voiceRecording` | 录音和 STT | 工具按钮隐藏，开始函数也拒绝 | D17 已延期；仍可输入文字 |
| 拍照 `camera` | 输入工具调相机，生成附件 | 相机按钮隐藏 | 既定延期；已有图片选择仍属 P0 |
| 保存相册 `gallerySave` | 附件图、Mermaid 图写相册 | 保存按钮隐藏；查看和源码复制保留 | 既定延期；与“读取用户选中的图片”分开 |
| 系统分享 `outgoingShare` | 日志等分享给其他 App | 分享按钮隐藏，创建分享文件前门禁 | 既定延期；日志查看/复制保留 |
| 完整网络状态 `networkStatus` | 介质、IP、速率等设备遥测 | 完整 API 拒绝；NWPath 恢复事件另行存在 | 既定延期，不能用 connected Bool 冒充完整设备信息 |
| 设备分布式节点 `distributed` | AI 逐项授权使用手机工具、遥测 | 页面/监听/交互覆盖层不挂载；导入 Android enabled 设置也不会启动 | 完整 Distributed 已延期；服务端聊天工具不因此全部禁用 |

这 13 项当前均为 `unsupported`，技术枚举没有进一步表达“平台机制不同”与“产品主动延期”。建议先在产品说明中准确解释；是否为 capability 新增原因字段，应由真实 UI 消费需求决定，不为表格形式复制状态。

## 3. 权限应如何向用户解释

| 类别 | 当前事实 | 建议告知/迁移方式 |
|---|---|---|
| Android 常驻能力 | 通知访问、OEM 自启动、电池优化、前台服务、WakeLock/helper 都是 Android 路径 | iOS 不显示“去开启同名系统开关”的引导 |
| 文件和图片 | iOS Files/PHPicker 尚未接入；D18 已定首期 | 在主动选择时解释操作范围，不复制 Android“全部存储授权”门禁 |
| 延期敏感功能 | 相机、麦克风、相册写入、GPS/设备工具、系统通知尚未开放 | 首期不提前请求；恢复 adapter/入口时再定义权限、拒绝、设置跳转 |
| 局域网 | D7 首期需求；当前 Info.ios.plist 仅有 Scene 输入 | Phase 3 核对 LAN 用途、Rust/WebKit transport 和拒绝后的恢复；NWPath 不是授权凭据 |
| Root / APK / 跨 App 悬浮 | 不能照搬成 iOS 设置项 | 说明 Android 专属或退役，不要求用户寻找对应权限 |

本阶段新增的两个 Swift 接口只有能力查询与事件注册，尚未新增相机、照片、麦克风等授权请求。权限声明存在、能力标记 implemented、当前已获授权，三者不能混同。

## 4. 命令与 AI 设备工具覆盖

当前自有插件前端注册 **42 条**，`build.rs`、`src/lib.rs` 与 permission 包集合一致。Android main 显式授予 22 条；iOS main 对自有插件授予 **0 条**，仅有 `core:default`、`opener:default`。Swift 两个内部 selector 由 Rust 调用，不需要为它们放开前端 ACL。

以下是执行结果分类，**不是**旧研究 R/S/L/X 迁移分类。对正常 iOS 前端，ACL 会先阻止自有插件 invoke；下面是其 Rust iOS 分支本身的防线。

| iOS 返回 | 当前命令 |
|---|---|
| `not_implemented`，11 条 | `set_keep_screen_on`、`clear_keep_screen_on`、`acquire_foreground`、`release_foreground`、`get_free_disk_space`、`pick_file`、`get_battery_status`、`open_file_native`、`save_to_downloads`、`write_temp_file`、`delete_temp_file` |
| `unsupported`，31 条 | `start_helper_service`、`check_all_permissions`、`request_android_permission`、`move_task_to_back`、`check_notification_listener_permission`、`request_notification_listener_permission`、`request_auto_start_permission`、`request_power_management_permission`、`check_auto_start_permission`、`get_network_status`、`capture_window_snapshot`、`save_image_to_gallery`、`save_image_from_path`、`start_download_notification`、`update_download_notification`、`cancel_download_notification`、`get_pending_notification`、`register_shared_files`、`get_cpu_thermal_status`、`get_gpu_status`、`check_root_access`、`run_root_command`、`launch_root_manager`、`acquire_wake_lock`、`release_wake_lock`、`start_network_monitoring`、`verify_apk_signature`、`can_install_packages`、`open_unknown_sources_settings`、`acquire_ota_keepalive`、`release_ota_keepalive` |

`open_file_native(action=share)` 子动作另返回 `unsupported`。Kotlin 的 59 个原生命令还包含内部 CLI/媒体/传感器等调用，不能当成 59 个前端权限。宽的 default/all permission 包当前没有被 app capabilities 引用，不是正在生效的全量授权。

Distributed 当前注册 **14 个**真实工具，iOS 整体不开放：

| 类别 | 工具 | 后续审议边界 |
|---|---|---|
| 基础操作 | 设备信息、系统通知、剪贴板、VCPMobileCLI | 通知/剪贴板未来可以另议；CLI 涉及不同运行时，不做空成功适配 |
| 系统遥测 | 电池、内存、CPU、GPU、网络、存储 | 逐字段核对来源，缺失值不能填 Android 模拟数据 |
| 传感器 | 位置、运动、环境 | 分别定义可取得字段、权限和前后台条件 |
| 聚合 | 整机状态摘要 | 只聚合真正已经实现的数据 |

**AI 剪贴板工具延期不等于普通复制/粘贴被禁用。**消息/HTML/Mermaid 等仍使用共享 Web Clipboard 路径，但尚无 iOS 运行验证。浮动助手在 Android 当前也已暂停，入口处于注释中，不把它算作本轮 iOS 删除的正常功能。交互式拍照工具只在注册表注释中，不能凭存在源码就列为已上线。

媒体处理还有能力表外的边界：非 Android 图片/音频存在小于 5,000,000 字节原样 base64 的共用回退，没有 iOS 原生缩放/音频转码 adapter；视频抽帧明确未支持。这些不构成原生媒体完成证据，后续需按媒体预算和既定范围复审。

## 5. 供用户审议的告知方式

D6 提供隐藏入口或解释不可用原因的既定方向。**本轮建议主要操作隐藏，在关于页集中说明；仍可点击的入口给出具体原因；运行故障在发生时提示。**其中“关于页集中说明”属于 U1 待审建议，并非 D6 已批准的页面方案。以下均未落地。

| 编号 | 需审议的表达 | 建议方案 | 替代选择及代价 |
|---|---|---|---|
| U1 | 隐藏功能如何让用户知道 | 关于页增加线性的“iOS 实验版功能说明”，区分已接入/接入中/本版暂不提供/Android 专属 | 全部显示灰色入口更易发现，但会增加无效操作；只隐藏则仍缺解释 |
| U2 | 头像、附件等仍可点入口 | 保留现有数据展示，阻止未实现动作并给出具体说明 | 彻底隐藏操作更安静，但已有用户难以理解差异 |
| U3 | 后台功能未接入期间 | 在用户开始相关长任务时就近提示当前限制，不在每次启动反复弹窗 | 仅写关于页干扰更少，但用户容易在任务中切后台 |
| U4 | 延期功能是否调整优先级 | 继续沿用 D9/D10/D17 与既定延期，不自动扩大首期 | 若要提前通知/语音/分享等，需同时调整 adapter、权限、UI 与验收范围 |

建议文案：

| 场景 | 建议用户文案 |
|---|---|
| 头像选择尚未接入 | 当前 iOS 版本尚未接入头像选图，现有头像仍可正常使用。 |
| 此类附件不能原生打开 | 当前 iOS 版本尚未接入此类文件的原生打开方式，附件仍保留。 |
| 后台 adapter 尚未接入 | 当前版本尚未接入 iOS 后台任务，请保持应用在前台完成操作。 |
| 系统通知延期 | 本版仅提供 App 内通知，系统通知暂未接入。 |
| 语音/相机延期 | 本版暂未提供语音输入和直接拍照，可继续输入文字或选择已有图片。 |
| Android 专属安装方式 | APK 应用内更新仅适用于 Android；iOS 实验版需在应用外自行签名安装。 |
| 原生订阅真正失败 | 原生状态监听未能建立，部分恢复功能暂不可用。请关闭并重新打开应用。 |

真正的系统授权拒绝应写“未获授权”并给出实际可用的恢复动作；不能用“尚未适配”掩盖拒绝，也不能用“请打开权限”解释没有实现的功能。普通暂缓功能不需要逐条产生常驻错误通知。

当前需要修正的具体误导包括：头像报“头像读取失败”容易被理解为图片坏了；附件报“无法打开附件”没有解释平台阶段；原生订阅失败仅建议保持前台；未来 Files 导出若只翻转 capability，会留下“已导出到 下载/VCPMobile”和“系统下载目录”的 Android 文案。
