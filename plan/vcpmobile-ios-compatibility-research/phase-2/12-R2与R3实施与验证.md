## 2. 与方案的 API 细化

锁定 Tauri 2.12.1 的 `Manager::get_window/windows/get_webview` 受 `unstable` feature 限制。本次不开启该特性：先用公开 `get_webview_window("main")` 检查正常注册；读取其实际 `Window::scene_identifier()` 核对 session。

不存在正常 WebView 时，`from_config/build` 沿 Tauri 自身的 `prepare_webview/prepare_window` 检查真实注册表。同名残缺注册会在 `runtime.create_window` 前返回 `WebviewLabelAlreadyExists/WindowLabelAlreadyExists`，被明确记为注册不一致，不删除旧窗口、不创建副本。当前 main 配置下此前的准备工作只构造 pending 数据、初始化脚本与闭包，不 attach 原生窗口或运行 Swift `load`。

UIKit 读取直接依赖仅声明在 iOS target 下，版本沿用锁定的 `objc2 0.6.4`、`objc2-ui-kit 0.3.2`。没有添加 Foundation 直接依赖；role 使用 Apple 导出常量，Scene 使用对象身份比较。

Tauri 当前没有目标 `window_scene(...)` API。恢复仍依赖 tao 在禁用多 Scene 时选择唯一候选，随后核对实际绑定；`requested_by_scene_identifier` 不是目标绑定，不能代替该检查。创建后绑定异常只记录错误，不自动销毁/循环创建；创建失败且无主窗口时，下一次真实 Scene 请求可以重新尝试。

## 3. 所有权与故障生命周期

- `lib.rs` 只同步转交 iOS RunEvent 并记录错误，窗口装配由 `infra/ios_window.rs` 承接。
- Swift、原生长期 Channel 和 Rust 领域状态继续沿现有 owner 存活；重建只创建新的主 WebView 与前端 Pinia。
- `receive_native` 的独立任务在外层取消后继续持有接收端，真实回调完成才释放注册槽。订阅的晚到成功、reject、解析失败与协议错误都有原订阅任务消费；能力查询超时仅属于此提交的历史路径。
- `ServiceFailureNotices` 记录故障事实，`collect_service_failure_notices` 在同一锁内收集并仅保留 `Events`。两平台当前均无进程内订阅重试；未来若引入成功恢复，须同时调整留存期限。
- `oncePerWebview` 是前端本地呈现字段。Store 私有、不持久化的 Set 在 `silent` 之后、既有重复通知规则之前记住显式 ID，记录的是已接受告知，不是用户已读。
