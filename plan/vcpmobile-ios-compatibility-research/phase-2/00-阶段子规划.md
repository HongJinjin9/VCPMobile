## 1. 初次施工输入（2026-10-08 历史基线）

- Phase 1 已有 24 项 typed capability、iOS/Android/host 分支、main ACL、目录 owner 和 lifecycle DTO。当前 iOS 插件 state 仍是 marker，未注册 Swift。
- `events::subscribe`、Rust native sequence 排序器和 bootstrap 的 Channel 安装当前仅编译 Android；Vue 已消费 Rust 的 lifecycle snapshot/epoch。不能只增加 Swift 文件而漏掉这些入口。
- app command `get_platform_capabilities` 当前是纯编译目标查询；本阶段让 iOS 返回真实 Swift adapter 观测，但不将尚未接通的文件、后台等能力标为已实现。
- 锁定 Tauri 2.11.5 / CLI 2.11.4 / tao 0.35.3。iOS deployment target 为 15.0；tao 的 Scene gate 与原生异步回调取消风险必须按锁定源码闭环。
- 工作树原有 package、pnpm lock、app build.rs 和六份 autogenerated permission 修改不属于本任务，保存 SHA-256 后保留。Phase 1 HEAD 已提供可恢复点，无需新增 checkpoint。

依据：[Phase 1 交接](../phase-1/07-验收与Phase2交接.md)、[依赖审计](../phase-0/03-依赖目标与Apple工程输入审计.md)。

## 2. 当前阶段边界（2026-10-09 校准）

保留 Swift Package、FFI 注册、lifecycle/network Channel、单 Scene 工程及恢复与 G1 手动构建入口。初次方案的能力查询、四轴表和前端平台 Store 已撤销；平台身份由 OS 插件同步注入。Swift 仅持有原生观察资源，业务状态与终态仍归 Rust。NWPath 连接事实不代替服务器可达性或完整设备遥测。

Files/PHPicker/ImageIO、Insets/键盘、Chat/Sync 后台收尾、continued processing 和用户自签打包仍在后续阶段。Android 原有注册、生命周期租约与数据目录保持；不建立 iOS 实机测试体系。

## 3. 逐路径任务及当前处置

| 任务与 owner | 输入 → 输出 | 异常、取消与资源释放 | 验证与依赖 |
|---|---|---|---|
| plugin `ios/Package.swift` 与 Swift plugin | 本地 Tauri API → 静态 product / `init_plugin_vcp_mobile` | minimum 15.0；初始化与 selector 明确匹配，失败返回 reject | 锁定 API/ABI 审计；G1 编译与链接 |
| plugin `src/lib.rs`、`build.rs` 与 iOS bridge | `ios_path` → register_ios_plugin → 真实 handle | 不借用 host fixture；单次订阅独立接收真实结果；调用方取消不丢 receiver | 取消与最终响应行为检查；G1 编译/链接 |
| 原能力查询任务（已撤销） | 删除 Swift/query/app DTO/前端 Store，改为 OS 插件同步身份 | 启动不再等待能力响应；实际权限和执行结果归真实操作 | 检查共享启动与实际差异入口，不恢复矩阵测试 |
| Swift app/Scene 与 NWPathMonitor | 原生事实 → 同一 Channel，注册时回放已知 snapshot | phase 去重、进程单调 sequence；网络未知不伪造离线；旧订阅/monitor 回调按 generation 丢弃并释放 | active/inactive/background、重复、回放、替换和迟到分支审计 |
| `lifecycle_state/controller/manager` | native event → 原 Rust 排序器/epoch/snapshot → Vue | 首次真实输入前 null；拒绝重复/旧 sequence；保留 Android linger，iOS 不启动 Android service | 定向 Rust/TS 生命周期检查；生产链 cfg 回扫 |
| Vue `useAppLifecycle` | iOS native online → 既有 interrupted stream reconcile | READY、native active、document visible、同一 recoveryPromise 与卸载释放 | 监听失败/卸载/重复恢复检查；不建立第二份网络状态 |
| iOS 配置、plist/privacy 与工程脚本 | 受版本管理输入 → 可重建 Apple 工程 | 使用官方 tao；R2 应用窗口恢复已有独立 owner；各 package 正常解析，无集中 Swift lock/shim | G1 保存实际工具诊断和 archive 供审查，见 10 |
| 手动 G1 workflow | 固定 runner/Xcode/toolchain → unsigned device debug archive 与诊断 | 不签名、不发布；保存输入、解析、编译和资源证据，失败定位后修复 | Windows 不能替代 Apple 编译；远端动作按根规则另行授权 |

## 4. 三方审查

- **Melchior**：`run_mobile_plugin_async` 的底层 receiver 不能随调用方 timeout/drop 而丢失；保留最终响应接收并限制未完成请求。native sequence 与 Rust epoch 各有作用域，不能混用。
- **Balthasar**：系统遮挡造成的 inactive 不是 background；原生读取在主队列，网络首次回调前保持未知；不制造假在线或假能力。
- **Casper**：当前保留唯一内部事件注册与一个事件源，复用已有领域 owner；G1 独立手动执行、工程改动可重放，不提前扩成发布或设备测试体系。

初次 tao 0.35.3 补丁已由官方 0.37.1 替代；后续发现的单窗口恢复和注册错误消费已按 11–13 实施。它们不要求恢复能力查询，也不替代 Phase 3 的业务输出接管。

## 5. 当前验收记录方式

1. 静态与 host：`pnpm check`、必要的 Rust/前端回归、补丁检查和原有修改哈希核对。
2. Android：按本阶段实际影响取得目标 Rust 检查；不将 host 结果代替 Android 或设备行为。
3. 工程输入：审查真实配置、资源、重放脚本和工具输出；不恢复已在 10 删除的静态等值、包白名单或集中 resolution 门禁。
4. G1：手动 Actions 执行 device debug archive 后记录对应 commit、Xcode/SDK、链接/资源检查及遗留诊断。执行前只能登记“待执行”，不能标记 Apple 已通过。

最终验收与 Phase 3 交接另文记录实际结果；独立阶段待办不阻止无依赖工作推进。
