# Phase 2：生产入口覆盖记录

> 2026-10-08。以下是本阶段生产调用链与源码检查结果，不是设备运行或 Apple 编译记录。

## 1. 入口到消费者

| 入口 | 实际路径与 owner | 本阶段结果 |
|---|---|---|
| Swift 静态链接 | plugin build.rs `ios_path` → Package product `tauri-plugin-vcp-mobile` → `init_plugin_vcp_mobile` → Rust binding/注册 | 四处名字对应；初始化返回值与锁定官方 opener 一致 |
| 前端启动能力查询 | 原 platform store → app IPC 总闸 → `get_platform_capabilities(AppHandle)` → plugin `ios::get_native_capabilities` → Swift `getNativeCapabilities:` | async 返回原 24 项契约；只提升 lifecycle implementation，runtime 来自原生观测 |
| 原生订阅 | Rust bootstrap READY 后 → `events::subscribe` → iOS bridge → Swift `registerNativeEvents:` | 一个 Rust 长期 Channel；Swift 注册并回放真实当前状态后 ack |
| Scene/App phase | UIKit 通知与状态 → Swift producer → `NativeLifecycleEvent` → native sequence gate → Rust epoch/transition lock → snapshot/event → Vue reducer | active/inactive/background 保留，旧 sequence 不占新 epoch，同相位首次快照可进入 owner |
| 网络路径 | NWPathMonitor 首次/变化 → `connected: bool` → native Channel → iOS `vcp-network-changed` → `useAppLifecycle` | 复用 interrupted stream recovery；仅作为重试提示，未知状态不伪造离线 |
| 恢复门控 | READY、原生 phase、document visibility → 同一 recoveryPromise | iOS 首次 snapshot=null 时禁止恢复；非 active/不可见禁止恢复；browser/native online 合并 |
| 超时和调用方取消 | plugin 两类原生请求 → 各一个原子在途槽 → 独立任务持有原生 receiver | 调用方 5 秒超时/丢弃不会取消底层接收；迟到响应安全消费并释放槽，重复未完成请求返回 busy |
| WebView/订阅替换 | Swift load → 原 Channel 的 replaceSubscription | 观察者和 monitor 先释放、generation 更新；旧回调不能发送到新订阅 |
| main ACL | app command 显式 main 窗口检查；iOS capability 沿用 core/opener | 两个 Swift selector 是 Rust 内部调用，不扩张公开 plugin 命令或前端原生权限 |
| 工程装配 | 受控配置/plist/privacy/resolution → CLI 生成 → XcodeGen overlay → G1 archive 检查 | 输入可重放；实际 Apple 结果待 G1 |

## 2. 集合与 Android 兼容范围

运行 Phase 0 历史抽取器读取当前源码，未覆盖其 evidence：

- 42 条公开 plugin endpoint、176 条 app command、59 条 Kotlin selector，数量不变。
- 22 条有活跃前端消费者的 plugin endpoint、11 条 Rust-only、9 条未找到消费者，数量不变。
- 0 条活跃未知前端命令、0 条动态 invoke；九组 permission 集合均为 42，无差异。
- 历史工具返回退出码 **1**：它只把 Kotlin `@Command` 作为 native selector 集合，新增 Swift `getNativeCapabilities` 造成 1 条 unmatched。该工具不展开 cfg，也不读取 Swift，不能把这个结果称为完整移动端审计通过。
- 人工按当前 iOS 分支核对：`getNativeCapabilities` 与 `registerNativeEvents` 均存在 Swift `@objc` producer；后者原已是 Android selector。此次没有给 Kotlin 增加虚假同名实现，也没有放宽旧工具断言掩盖平台差异。

Android 的 native handle、订阅请求、Kotlin producer、公开命令与 ACL 保持原路径；本阶段只将需要共享的 lifecycle 入口扩到 iOS。Android foreground service/linger 仍在原分支。tao override 对所有 Cargo target 生效，但差异仅在三个 iOS 文件，其余 115 个源文件保持上游原字节。

## 3. 有界资源与具体限制

- 每进程一次 Rust Channel；Tauri 2.11.5 的 mobile Channel 全局表没有删除接口，不能用无限创建 Channel 来重试。
- Swift 每实例一个 NWPathMonitor、一组固定数量通知观察者、一个 Channel；替换时取消旧 monitor/观察者，闭包弱引用并检查 generation。
- 两个原生 selector 各最多一个底层在途任务。主队列暂时不执行时任务等待但不会因用户不断重试而无限增加。
- 调用方超时不代表原生注册失败；迟到成功仍可输送事件。真正 reject 或 Swift source failure 当前需用户重新启动 App，能力查询重试不会重建订阅。
- Channel 能力与设备遥测分开；除 lifecycle 外，iOS 其余 capability 沿用待实现或延期状态。
- native background 现在会更新既有 Rust foreground state；日志缓冲、回前台 flush、Chat/Sync 有界收尾仍交 Phase 3 沿现有领域 owner 处理。
