## 2. 核对结果

| 路径 | 复审结果 |
|---|---|

| 恢复后的状态 owner | 新 WebView 沿框架触发 Swift `load`，现有 Channel 复用、观察资源替换；Rust bootstrap 不重跑，前端新 Pinia 重新取得系统快照 |

| [events.rs](../../../src-tauri/plugins/vcp-mobile/src/events.rs) 故障留存 | 同一锁内收集并仅保留 Events；Guardian/Helper 继续取走；真实订阅仍只有一次，没有新建 Channel 重试或无界任务 |
| [通知 Store](../../../src/core/stores/notification.ts) 与实际入口 | 实时事件及系统快照经过同一 processor/Store；私有 Set 在 silent 检查后按固定 ID 接受一次，清历史和 Toast 不重置，新 Pinia 可重新接受 |
| Android 与公共提示 | 新通知选项只用于 Events；Guardian/Helper 和其他通知继续原语义；公共错误提示不依赖可能尚未加载的平台快照，不传递原始原生错误详情 |
| 依赖和装配 | 新窗口模块及 UIKit 依赖限定 iOS；Cargo.lock 仅增加根包对已有两项依赖的引用，未改变版本；app IPC 总闸及现有状态装配保持 |

## 4. 保留的限制与交接

- **Apple 构建：**G1 仍需提供 iOS cfg 的真实类型检查、UIKit/Swift 链接和 archive 事实。源码中的签名核对不能替代该结果。
- **运行时行为：**UIKit 重连回调时 connectedScenes 的内容、窗口 attach/显示时序尚无实际观察；G1 编译通过也不能证明这些运行结果。项目仍不建设 iOS 实机测试体系。
- **窗口恢复失败：**创建或绑定检查失败时记录错误；没有 WebView 就无法通过前端 Toast 告知。无窗口时后续真实 Scene 请求可以再次尝试，已创建但绑定异常的窗口不会被自动循环销毁重建。这是现有错误路径的能力边界，不是本轮新发现的确定性故障。
- **聊天流接续：**运行中的 Rust Chat 任务向新 JS Channel 交付输出仍属 Phase 3；窗口恢复、Rust 状态存活不表示用户会无缝收到旧任务输出。
- **真实注册失败：**当前没有进程内恢复入口，Events 故障保留到进程结束。将来若增加成功重试，需要一起调整故障留存和提示语义；本次没有引入这种恢复路径。
