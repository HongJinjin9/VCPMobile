## 源码与编译语义推演方法

| 步骤 | 分析内容 | 必须留下的结果 |
|---|---|---|
| 固定输入 | commit、锁定包、target、features、deployment target | 可复查的文件与版本 |
| 展开目标路径 | `cfg`、宏注册、模块可见性、目标依赖 | Apple 实际参与的定义和引用 |
| 类型与调用 | trait bounds、泛型、Send/Sync、Swift selector、DTO 编解码 | 参数/返回/错误逐字段对应 |
| 原生构建 | build script 分支、C/C++ 文件、SDK/framework、FFI ABI | 编译参数、符号生产者与消费者 |
| 工程装配 | SwiftPM product、Rust archive、资源、plist、ACL | 从源码到 app bundle 的连接关系 |
| 行为推演 | identity、乱序回调、取消、释放、持久化 | 每条终态与资源归属 |
| 检查执行 | 日常 host 辅助工具、阶段性 GitHub Actions 构建与包检查 | 实际命令、输入、诊断与产物 |

逐项给出“已定位的源码事实”“由条件推出的结论”“实施动作”。例如：`htmd 0.5.5` 的 manifest 声明 `build = false`，普通依赖是 HTML parser 与表驱动转换组件，因此它自身的接入重点是 Rust 类型和功能调用；SQLite/zstd 则须继续分析 C 编译与 archive 链接。

### 待办记录格式

```text
对象与版本 → 源码/声明位置 → 输入条件 → 推导结果
          → 具体改动 → 剩余问题 → 获取信息的方法
```

缺少一个声明时，先查本地 registry、锁定 tag 的上游源码、公开接口或 SDK 声明。只有具体问题影响到的任务依赖它，其余实现继续推进。平台身份只描述运行 OS；权限、连接、任务与导出结果由其实际 owner 返回。研究进度和批准范围留在文档，不生成强制的运行时能力状态机。
