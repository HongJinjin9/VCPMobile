### 推荐目标结构

```text
Vue / Pinia
  └─ typed PlatformCapabilities + typed platform facade
       └─ Tauri IPC（平台中立命令/DTO）
            ├─ Rust domain owners
            │    Chat / Sync / Persistence / Files / Distributed
            └─ MobilePlatform adapter
                 ├─ Android Kotlin + JNI/Channel
                 └─ iOS Swift + C FFI/Channel
```

必须维持的 owner 不变量：

- Chat attempt、Sync session、数据库、附件 CAS 和 Distributed client 仍由 Rust 唯一拥有；
- Swift 只报告 app phase/network/权限事实，呈现 picker/share/system UI，并持有 Apple task token；
- SSE、同步队列、重试与恢复继续归现有 Rust owner；
- Vue 消费 capability 和领域结果，入口呈现由这两个来源驱动；
- 平台支持、实现、授权、即时条件分别表达；研究记录集中在 00。

### Swift 插件的完整注册链

```text
build.rs .ios_path("ios")
  → tauri-plugin/build/mobile.rs → Swift Package 静态库
  → ios_plugin_binding!(init_plugin_vcp_mobile)
  → register_ios_plugin(init_plugin_vcp_mobile)
  → VcpMobileState.plugin_handle
  → run_mobile_plugin[_async](命令名, DTO)
  → Swift @objc selector → Invoke.resolve/reject / Channel.send
```

具体模板可取自锁定的 `tauri-plugin-opener 2.5.4/ios/Package.swift` 与 `Sources/OpenerPlugin.swift`。`tauri-plugin 2.6.3/src/build/mobile.rs` 将 Tauri API 复制到 `.tauri/tauri-api`，`tauri-utils 2.9.3/src/build.rs::link_apple_library` 处理 SwiftPM 与部署版本。核对 Swift package product、库名与 Rust binding 符号的一致性。

`tauri 2.11.5/mobile/ios-api/Sources/Tauri/Tauri.swift` 的 `PluginManager.invoke` 使用 `DispatchQueue(label: "ipc")`，按 ObjC selector 分发。由此得到三项实施要求：UIKit 调用显式进入主队列；复制/解码安排工作队列；Rust serde 键、Swift Decodable/CodingKeys 与 TS DTO 逐字段对照。

同目录 `Channel.swift` 已能解码 `__CHANNEL__:<id>` 并回传 Rust，`Invoke.swift` 提供编码返回值和结构化拒绝。Swift 在 `registerNativeEvents` 保存 Channel、回放快照，再发送生命周期和网络变化；Rust 继续归约到现有 transition epoch。

桥接取消需单独处理：锁定版本 `src/plugin/mobile.rs::run_mobile_plugin_async` 的回调对 oneshot send 使用 `unwrap()`。业务超时若直接丢弃等待 future，迟到回调会进入这一错误路径。让受控桥接任务接收原生最终响应，业务 owner 按 generation 决定消费或丢弃结果，并在原生终止后回收桥接任务。

### cfg 与错误语义

稳定结构应显式拆成：

```rust
#[cfg(target_os = "android")]
// Android production

#[cfg(target_os = "ios")]
// iOS adapter

#[cfg(not(any(target_os = "android", target_os = "ios")))]
// host test/development scaffold
```

命令返回值按实际原因区分：

- `unsupported_by_platform`：平台没有安全等价；
- `unsupported_by_product_scope`：平台可做但不进入当前实验范围；
- `not_implemented`：计划内但尚未施工；
- `temporarily_unavailable`：实现存在但当前授权/运行条件不满足。

成功结果携带实际路径、授权状态或操作结果。已有固定容量/电量等 host 数据留在开发分支；iOS 通过对应 adapter 获取。

### 数据与网络边界

- SQLite 建议继续放 `app_config_dir/app_data_dir` 内；附件 CAS 用 `app_data_dir`，瞬时 picker/security-scoped 副本和大文件上传用 `app_cache_dir`；
- 外部 security-scoped URL 不进入长期数据库；Swift 在授权窗口内复制到 staging，再由 Rust hash/CAS；
- Rust HTTP/WebSocket 在 transport owner 执行 scheme、证书和受信 LAN policy；WebKit/URL Loading 路径配置对应 ATS 项；
- LAN 使用说明、拒绝后的可恢复错误与设置返回重试纳入功能实现；
- `127.0.0.1` 高速上传沿现有 token、长度与 CAS 链审查，补前端 abort 和过期回调处理，见 05。

### 最小改造顺序

1. 固定目标配置、能力映射与共享 owner；
2. 拆 cfg/ACL，定义真实 DTO 与路径；
3. Swift Package、binding、Channel 和生命周期接入；
4. Chat/SQLite/Settings/Sync 与原生附件链；
5. attempt/task identity、进度适配、终态及尽力后台；
6. 工程装配、构建脚本和用户自签产物。

每项按源码推演、实现与缺陷回扫推进；Apple 构建仅在 G1 插件接入、G2 首版集成/打包验收时通过 GitHub Actions 手动执行。检查细目见 07。
